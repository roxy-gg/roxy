# Wallpaper Workshop

Custom uploads are retained in **My Backgrounds**, after the Add your own tile and before catalog results. Each card shows a **Custom** badge until a public catalog lookup confirms publication. Uploading selects the saved card automatically; browsing highlights a card while a separate **In use** checkmark identifies the applied wallpaper. Custom cards offer reuse, rename, and confirmed deletion. Sidebar > Remove clears the active image without deleting the saved library. Deleting an active card clears that background, while deleting an inactive card leaves the current background alone.

The library keeps normalized media in private `userData/chat-backgrounds/<content-sha256>.json` assets, with bounded static WebP thumbnails and metadata in `chat-background.json`. The renderer receives summaries, not all full media. Duplicate uploads reuse and repair the existing asset, retaining its name/publication history. The library is limited to 50 entries and 350 MiB of retained data; adding at capacity returns an actionable error rather than silently evicting personal media. Legacy local backgrounds are preserved during migration. Profile locking and rereading committed state protect concurrent app processes; factory reset removes the manifest and all retained assets.

Successful submissions retain up to ten receipt IDs so approval of an earlier submission is still recognized. Submission is not publication. Public detail lookups are bounded, run in the main process, and distinguish authoritative 404 (not public) from offline/failed checks (keep last confirmed status). The active view refreshes on focus and once per minute, with throttled publication checks. No new uploads occur during refresh; only receipt IDs are checked. A confirmed publication removes the Custom badge and hides resubmission; a later authoritative withdrawal restores Custom. Local-library identity remains distinct from catalog-use reporting.

Settings > Background opens the Workshop with an Add your own tile first, followed by ten Most Used results. The custom tile stays available while loading, searching, and when the catalog is empty or unavailable. Add Custom Background opens the same local picker. Search title/tags, filter images/silent videos, switch between Most Used and Recent Approved, and load ten more on demand. Cards show titles and video indicators, not dimensions or device counts. Selecting a card uses only its cached still thumbnail, including video cards; it never requests the full wallpaper. Only Use background fetches approved media through the main process, validates MIME/size/SHA-256, imports it with the existing decoder, and persists a device-local copy. Settings/effects stay unchanged; remove/reset/newer imports supersede pending catalog downloads. Settings > Sidebar, directly below Background, contains the live preview, effects, sidebar style/opacity, chat visibility, glass composer, Remove, and Reset effects.

Local upload selection saves automatically without a separate Save action. Submit for review appears beside Use background / In use in the selected unpublished local card detail view, with a preview and its form below. It does not appear in the catalog header. Inactive local cards can be submitted without applying them; the main process reads and validates that specific retained asset, binds consent to its immutable content hash, and records its receipt without changing the current background. Catalog backgrounds cannot be resubmitted. The form includes title, optional description and author, a required license dropdown (or custom permission/source details), and explicit rights/upload consent. Tags are generated locally from the title and media type and remain editable as chips: Enter/comma commits, paste splits lists, Backspace/removal deletes, duplicates are normalized, and the serialized list is limited to 200 characters. Manual edits survive title changes. Consent is bound to an immutable SHA-256 image snapshot; cross-window changes reject submission rather than uploading a different background. The sender must be the app's trusted main frame. No provider keys, accounts, telemetry identifiers, paths, or background-effect settings are submitted.

Videos/GIFs are normalized by roxy.gg to silent H.264 MP4; source audio/metadata is removed before durable storage. Media is private until staff approval. Staff use roxy.gg/wallpapers/review. The backend and deployment setup are documented in the sibling `roxy.gg/docs/wallpapers.md`.

`ROXY_CATALOG_BASE` defaults to `https://roxy.gg`; only HTTPS or loopback HTTP origins are allowed. The main process fetches fixed first-party `/thumbnail` routes, validates static WebP dimensions/size, and stores them in `userData/wallpaper-thumbnails`. The cache key includes origin, wallpaper UUID, content SHA-256 and thumbnail-format version. Concurrent requests share a fetch; writes are atomic; corrupt entries are replaced; cache write failures do not break browsing. Least-recently-used eviction caps it at 500 thumbnails / 50 MiB. Renderer previews receive data URLs, never local filesystem paths or remote media URLs. The server does not cache generated thumbnails.

Successful catalog imports atomically save `catalogId` with the background. Local replacement, removal and factory reset clear it; Reset effects keeps it. Existing backgrounds saved before catalog identity support remain untracked until reapplied from the Workshop. The main process keeps one random wallpaper-specific installation ID and sequence in `userData/wallpaper-device.json`, unrelated to analytics or accounts. It reports only that device ID, current catalog wallpaper UUID (or null) and monotonic sequence, on startup/change and hourly while the app runs. Local-only users never mint/report an ID until using a catalog wallpaper. The server hashes the ID, maintains one current selection, counts devices seen in the last seven days and expires old records. Reports are serialized/coalesced, retried after network errors, and never block local background changes. A cross-process profile lock protects identity creation and sequence allocation; selection reconciliation reads committed background storage. Corrupt identity state is replaced with a new random ID (the old lease expires normally). An offline clear is reconciled on restart. Quitting does not clear the configured background; absence of heartbeats eventually expires its count. No provider keys, local-upload content, titles, or hardware IDs are included.

Tests: `npm run smoke:wallpapers`, `npm run smoke:wallpapers-ui`, `npm run smoke:background`. Build roxy.gg first, then `npm run smoke:wallpapers-admin-ui` for the staff page's browser behavior. Dedicated UI smoke tests use port 3102 and mocked transports; backend tests exercise real migration/service SQL and authorization middleware separately. New locale keys have generated English fallback until translated.
